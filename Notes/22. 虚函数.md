### C++ 虚函数核心笔记

- **1. 虚函数的核心作用**
  - 在面向对象编程中，虚函数允许我们在子类 (Subclass) 中重写 (Override) 基类 (Base Class) 的方法。它是实现**多态 (Polymorphism)** 的关键特性。
- **2. 为什么需要虚函数？**
  - 默认情况下，如果你使用基类的指针或引用指向一个子类对象，并调用某个方法，编译器会静态绑定并直接调用**基类**的该方法。
  - 在基类方法前加上 `virtual` 关键字，可以告诉编译器进行动态分发，确保在运行时根据**实际指向的对象类型**来调用对应的子类重写方法。
- **3. 底层机制：V-Table (虚表)**
  - 虚函数通过**动态分发 (Dynamic Dispatch)** 实现，编译器底层通常会生成一个虚函数表 (V-Table)。
  - V-Table 包含所有虚函数的映射关系，确保程序在运行时能正确找到并调用子类覆盖后的函数。
- **4. `override` 关键字**
  - C++11 引入了 `override` 关键字。在子类中重写虚函数时，虽然不写也能运行，但强烈建议在方法末尾加上它。
  - 这不仅提高了代码可读性，还能让编译器帮你检查出拼写错误或函数签名不匹配等低级 Bug。
- **5. 虚函数的额外开销**
  - **内存开销**：需要**额外的内存**来存储 V-Table，且包含虚函数的类实例中会多出一个指向该 V-Table 的指针。
  - **性能开销**：每次调用虚函数都需要在运行时查表，会带来微小的性能损耗。
  - **结论**：除非你在编写对性能要求极其苛刻的嵌入式系统，否则这种微小开销几乎可以忽略不计，不应因此而拒绝使用虚函数。

### 相关示例代码

```
#include <iostream>
#include <string>

// 基类
class Entity {
public:
    // 将方法标记为虚函数 (virtual)
    virtual std::string GetName() {
        return "Entity";
    }
};

// 子类
class Player : public Entity {
private:
    std::string m_Name;
public:
    Player(const std::string& name) : m_Name(name) {}

    // 重写基类的虚函数，并使用 override 关键字
    std::string GetName() override {
        return m_Name;
    }
};

void PrintName(Entity* entity) {
    // 因为基类中的 GetName 是虚函数
    // 这里会通过 V-Table 找到并调用传入对象的真实类型对应的方法
    std::cout << entity->GetName() << std::endl;
}

int main() {
    Entity* e = new Entity();
    PrintName(e); // 输出: Entity

    Player* p = new Player("Cherno");
    PrintName(p); // 输出: Cherno

    // 多态的体现：使用基类指针指向子类对象
    Entity* poly = new Player("Polymorphic Player");
    PrintName(poly); // 输出: Polymorphic Player

    delete e;
    delete p;
    delete poly;

    return 0;
}
```
