# C++ 笔记：使用动态库 (Using Dynamic Libraries)

## 1. 动态链接的核心概念

- **运行时加载**：与静态链接在编译时将代码打包进可执行文件不同，动态链接（Dynamic Linking）发生在**运行时 (Runtime)**。动态库（如 Windows 下的 `.dll` 文件）是在程序启动或运行过程中被加载到内存中的。
- **动态链接的两种方式**：
  1. **隐式/启动时加载（重点）**：可执行文件在编译时就知道需要这个动态库。程序启动时，操作系统会自动寻找并加载所需的 `.dll`。如果找不到，程序会直接报错（如 "DLL was not found"）。
  2. **显式/运行时加载**：程序在代码中手动调用操作系统的 API（如 Windows 的 `LoadLibrary`）来动态加载库，并手动获取函数指针。

## 2. 配置隐式动态链接 (以 GLFW 为例)

在 Visual Studio 中配置动态库与静态库的步骤非常相似，但有一些关键区别：

1. **包含目录 (Include Directories)**：配置头文件路径，与静态链接完全相同。
2. **配置链接器输入 (Linker Input)**：你需要链接动态库对应的 **导入库 (Import Library)**。例如，不使用静态的 `glfw3.lib`，而是使用 `glfw3dll.lib`。这个 `.lib` 文件中并不包含实际的函数代码，而是包含指向 `.dll` 文件中实际函数位置的指针信息。
3. **放置 DLL 文件**：编译成功后，**必须将对应的 `.dll` 文件（如 `glfw3.dll`）复制到生成的 `.exe` 可执行文件所在的同一个文件夹中**。否则程序在双击运行时会因找不到依赖库而崩溃。

## 3. 示例代码

代码层面，调用动态库与静态库看起来是一模一样的（主要区别在于编译器和链接器的配置）：

```cpp
#include <iostream>
// 引入 GLFW 头文件，支持静态和动态链接
#include <GLFW/glfw3.h>

int main() {
    // 调用 DLL 中的初始化函数
    int result = glfwInit();
    std::cout << result << std::endl;

    std::cin.get();
    return 0;
}
```

*注意：在某些库（包括 GLFW）的高级用法中，你可能需要定义预处理器宏（如 `GLFW_DLL`）来启用 `__declspec(dllimport)`，但在许多现代库的默认配置中，即使不显式定义也能正常工作。*
