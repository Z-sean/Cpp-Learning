### Visual Studio C++ 调试核心笔记

- **1. 调试模式与前提**
  - 开始调试前，请务必确保在 Visual Studio 中选择了 **Debug 模式**。如果使用 Release 模式，编译器会优化和重排代码，导致断点无法准确命中或代码结构被改变。
- **2. 断点 (Breakpoints) 基础**
  - 按下 `F9` 或点击代码行号左侧边缘即可设置断点。
  - 当程序在断点处暂停时，会出现一个黄色的箭头。请记住：**黄色箭头指向的代码是“即将执行但还未执行”的代码**。
- **3. 关键的步进快捷键**
  - `F5` (Continue): 继续运行程序，直到遇到下一个断点。
  - `F10` (Step Over): 单步跳过，执行下一行代码，但**不会**进入代码所在函数的内部。
  - `F11` (Step Into): 单步调试，**进入**当前行调用的函数内部查看细节。
  - `Shift + F11` (Step Out): 步出当前函数，直接执行完该函数并返回到调用它的位置。
- **4. 查看变量与内存**
  - 可以通过 **Autos (自动窗口)**、**Locals (局部变量)** 和 **Watch (监视窗口)** 轻松跟踪当前变量的值。
  - 如果想查看底层数据，可以通过 `Debug -> Windows -> Memory` 打开内存视图，输入 `&变量名`（获取内存地址）来查看其底层的十六进制字节。
  - **关键特征：** 在 Debug 模式下，编译器会自动将未初始化的栈内存填充为十六进制的 `CC`，这能极大地帮助你一眼看出哪些变量忘记了初始化。

### 示例代码

视频中作者使用了一个简单的程序来演示如何一行行观察内存的变化：

```
#include <iostream>

int main() {
    // 在这里打个断点 (F9)，然后按 F5 开始调试
    int a;
    // 此时在 Watch 窗口看 a 可能是个垃圾值，
    // 在 Memory 视图输入 &a，会看到内存里全是 `CC`，代表未初始化栈内存

    a = 8;
    // 按 F10 走过上面这一行后，内存里的值会变成 8

    const char* string = "Hello";

    // 你可以按 F11 (Step Into) 进入自己写的函数内部，
    // 或按 F10 (Step Over) 直接跳过函数执行。
    return 0;
}
```

### 巩固测试题

既然我们还在专注练习模式，来试试这几道题吧：

1. 当调试器暂停时，黄色箭头指向的那行代码，是**已经执行完**的，还是**正准备执行**的？
2. 假设当前行有一个函数调用，如果你按下了 `F10` (Step Over) 会发生什么？如果你按下 `F11` (Step Into) 又会发生什么？
3. 如果你在调试时打开内存视图，发现某个变量的内存区域全都是 `CC` (十六进制)，这说明了什么？
4. 为什么进行代码调试时，必须使用 Debug 模式，而强烈不建议使用 Release 模式？
