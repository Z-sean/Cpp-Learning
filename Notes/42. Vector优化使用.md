# C++ 笔记：优化 `std::vector` 的使用 (Optimizing std::vector)

## 1. 核心问题：内存重新分配与拷贝

`std::vector` 的底层是连续的堆内存。当容量 (capacity) 不足以容纳新元素时，它会开辟一块更大的新内存，将所有旧元素**拷贝 (Copy)** 过去，然后再删除旧内存。这个自动重新分配的过程非常消耗性能。优化的核心目标就是**尽可能减少内存重新分配和对象的多余拷贝**。

## 2. 优化策略

### 策略一：按常量引用传参 (Pass by Const Reference)

当把 `vector` 作为参数传递给函数时，务必使用 `const std::vector<T>&`。如果直接按值传递，会导致整个动态数组被完整复制一次，产生巨大的性能浪费。

### 策略二：使用 `reserve()` 预先分配容量

如果你提前知道（或能估算出）`vector` 大致会包含多少个元素，请提前使用 `reserve()` 方法。

- `reserve(n)`：只预先分配足以容纳 `n` 个元素的内存，但**不构造**对象。
- 这能一次性把内存申请好，有效避免在循环添加元素时触发多次的自动扩容和拷贝。

### 策略三：使用 `emplace_back()` 代替 `push_back()`

- `push_back()`：通常会在当前作用域的栈上先构造出一个临时对象，然后再将该对象**拷贝**（或移动）到 `vector` 的堆内存中。
- `emplace_back()`：直接将构造所需的参数传递给 `vector`，在 `vector` 的实际内存位置**原地构造 (Construct in-place)** 对象，彻底消除临时对象的拷贝开销。

## 3. 示例代码对比

```cpp
#include <iostream>
#include <vector>

struct Vertex {
    float x, y, z;

    // 构造函数
    Vertex(float x, float y, float z) : x(x), y(y), z(z) {}

    // 拷贝构造函数：为了测试，每次拷贝时打印提示
    Vertex(const Vertex& vertex) : x(vertex.x), y(vertex.y), z(vertex.z) {
        std::cout << "Copied!" << std::endl;
    }
};

int main() {
    // ========== 【未优化版本】 ==========
    std::vector<Vertex> vertices;
    // 如果直接 push_back 3个元素：
    // 1. 触发多次容量不足导致的内存重新分配和拷贝。
    // 2. 每次 push_back 都在 main 函数栈上先构造临时对象，再拷贝进 vector。
    // vertices.push_back(Vertex(1, 2, 3));
    // vertices.push_back(Vertex(4, 5, 6));
    // vertices.push_back(Vertex(7, 8, 9));
    // 结果：会打印多达 6 次 "Copied!"

    // ========== 【优化版本】 ==========
    std::vector<Vertex> optimizedVertices;

    // 1. 预先分配能容纳 3 个元素的内存，避免自动扩容
    optimizedVertices.reserve(3);

    // 2. 原地构造元素，直接传入所需参数，避免从局部变量拷贝到 vector
    optimizedVertices.emplace_back(1, 2, 3);
    optimizedVertices.emplace_back(4, 5, 6);
    optimizedVertices.emplace_back(7, 8, 9);
    // 结果：0 次拷贝！性能大幅提升。

    return 0;
}
```
