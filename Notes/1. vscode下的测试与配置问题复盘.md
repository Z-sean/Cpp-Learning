# VS Code 配置 MinGW C++ 编译调试问题复盘报告

## 1. 问题背景

本次问题发生在 Windows 环境下使用 VS Code 学习 C++，工具链大致为：

```txt
VS Code
MinGW g++
MinGW gdb
PowerShell / Git Bash
tasks.json
launch.json
```

项目目录大致为：

```txt
VSCODE
├─ .vscode
│  ├─ launch.json
│  └─ tasks.json
├─ include
│  └─ test.h
└─ src
   ├─ main.cpp
   └─ tset.cpp
```

目标是通过 VS Code 实现：

```txt
编译 C++ 源码
运行 exe
断点调试
```

---

## 2. 问题一：preLaunchTask 退出代码 127

### 2.1 报错现象

VS Code 弹出：

```txt
preLaunchTask "task g++" 已终止，退出代码为 127
```

终端中出现类似：

```txt
bash: D:WorkDev-ToolsCpp...mingw64bing++.exe: command not found
```

### 2.2 问题原因

当时的 `tasks.json` 中 `command` 使用了 Windows 风格路径：

```json
"command": "D:\\Work\\Dev-Tools\\Cpp\\x86_64-8.1.0-release-posix-seh-rt_v6-rev0\\mingw64\\bin\\g++.exe"
```

但 VS Code 终端使用的是：

```txt
Git Bash
```

Git Bash 会把反斜杠 `\` 当作转义符处理，导致路径被错误解析。

例如：

```txt
mingw64\bin\g++.exe
```

可能会被解析成：

```txt
mingw64bing++.exe
```

于是系统找不到 `g++.exe`，报：

```txt
command not found
```

退出代码 `127` 的含义通常是：

```txt
命令不存在 / command not found
```

### 2.3 解决方案

将 `command` 改成正斜杠路径：

```json
"command": "D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin/g++.exe"
```

这样 Git Bash 和 PowerShell 都能更稳定地识别。

---

## 3. 问题二：g++ 找到了，但找不到源文件

### 3.1 报错现象

修改 `command` 后，`g++` 可以被找到，但出现新错误：

```txt
g++.exe: error: D:WorkComputer-LearningCpp-LearningCode-Practicevscode//src//*.cpp: No such file or directory
g++.exe: fatal error: no input files
```

### 3.2 问题原因

当时 `tasks.json` 中有：

```json
"args": [
  "-g",
  "${cwd}//src//*.cpp",
  "-o",
  "${fileDirname}\\${fileBasenameNoExtension}.exe"
]
```

同时又配置了：

```json
"options": {
  "cwd": "D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin"
}
```

这里有两个问题。

### 3.3 问题点 1：`${cwd}` 不是项目根目录

`cwd` 表示任务执行时的当前工作目录。

当时把 `cwd` 设置成了 MinGW 的 `bin` 目录：

```txt
D:/Work/Dev-Tools/Cpp/.../mingw64/bin
```

所以：

```json
"${cwd}//src//*.cpp"
```

实际含义接近：

```txt
D:/Work/Dev-Tools/Cpp/.../mingw64/bin/src/*.cpp
```

但源码实际在：

```txt
项目根目录/src/main.cpp
项目根目录/src/tset.cpp
```

所以 g++ 找不到源文件。

### 3.4 问题点 2：Git Bash 继续破坏 Windows 路径

在 Git Bash 下，路径里的反斜杠仍然可能被当作转义符处理。

所以终端里出现了类似：

```txt
D:WorkComputer-LearningCpp-LearningCode-Practicevscode//src//*.cpp
```

这明显不是一个正常的 Windows 路径。

### 3.5 建议解决方案

将源码路径改成基于项目根目录的路径：

```json
"${workspaceFolder}/src/*.cpp"
```

将输出路径也改成正斜杠：

```json
"${workspaceFolder}/src/main.exe"
```

更稳定的 `tasks.json`：

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "type": "shell",
      "label": "task g++",
      "command": "D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin/g++.exe",
      "args": [
        "-g",
        "-I",
        "${workspaceFolder}/include",
        "${workspaceFolder}/src/*.cpp",
        "-o",
        "${workspaceFolder}/src/main.exe"
      ],
      "options": {
        "cwd": "${workspaceFolder}"
      },
      "problemMatcher": ["$gcc"],
      "group": "build"
    }
  ]
}
```

## 4. 问题三：切换 PowerShell 后，调试器路径无效

### 4.1 报错现象

切换到 PowerShell 后，编译任务可以执行，但调试时报错：

```txt
Unable to start debugging. The value of miDebuggerPath is invalid
```

### 4.2 问题原因

`launch.json` 中的 `miDebuggerPath` 配置错误：

```json
"miDebuggerPath": "D:\\cppsoft\\mingw64\\bin\\gdb.exe"
```

但实际 MinGW 安装路径是：

```txt
D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin
```

也就是说：

```txt
g++.exe 使用的是一套 MinGW
gdb.exe 却指向了另一套不存在或错误的 MinGW
```

因此 VS Code 无法启动调试器。

### 4.3 解决方案

将 `miDebuggerPath` 改成真实存在的 `gdb.exe` 路径：

```json
"miDebuggerPath": "D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin/gdb.exe"
```

---

## 5. 最终成功原因

最后能够成功运行，主要是因为修复了两个关键问题：

```txt
1. 将 VS Code 终端从 Git Bash 改成了 PowerShell
2. 将 launch.json 中的 miDebuggerPath 改成了正确的 gdb.exe 路径
```

虽然 `tasks.json` 中的 `options.cwd` 没有修改，但因为 PowerShell 对 Windows 路径兼容更好，所以原本在 Git Bash 下会被破坏的路径，在 PowerShell 下可以正常执行。

需要注意：**能运行不代表配置设计最合理**。从长期维护角度看，仍然建议将 `cwd` 指向项目根目录。

## 6. 对 Git Bash 和 PowerShell 的理解

### 6.1 前端为什么常用 Git Bash？

前端开发中经常使用类 Unix 风格命令：

```bash
npm run dev
pnpm install
git status
rm -rf node_modules
mkdir -p
```

Git Bash 对这些命令支持较好，所以前端学习和开发中常用 Git Bash 是合理的。

### 6.2 C++ 在 Windows 下为什么建议用 PowerShell？

当前 C++ 学习环境是：

```txt
Windows
VS Code
MinGW g++
MinGW gdb
tasks.json
launch.json
```

这套链路中大量使用 Windows 路径。

PowerShell 对下面这种路径更友好：

```txt
D:\Work\xxx
D:/Work/xxx
```

而 Git Bash 更偏向：

```bash
/d/Work/xxx
```

所以在 Windows 下初学 C++ 时，更建议使用：

```txt
PowerShell
```

或：

```txt
cmd
```

而不是 Git Bash。

## 7. tasks.json 和 launch.json 的职责区分

### 7.1 tasks.json 负责什么？

`tasks.json` 负责“怎么编译”。

核心字段是：

```json
"command": "g++.exe 的路径"
```

例如：

```json
"command": "D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin/g++.exe"
```

`args` 负责告诉 g++：

```txt
编译哪些源文件
包含哪些头文件目录
输出到哪里
```

例如：

```json
"args": [
  "-g",
  "-I",
  "${workspaceFolder}/include",
  "${workspaceFolder}/src/*.cpp",
  "-o",
  "${workspaceFolder}/src/main.exe"
]
```

### 7.2 launch.json 负责什么？

`launch.json` 负责“怎么调试”。

核心字段是：

```json
"program": "要调试的 exe 路径"
```

以及：

```json
"miDebuggerPath": "gdb.exe 的路径"
```

例如：

```json
"program": "${workspaceFolder}/src/main.exe",
"miDebuggerPath": "D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin/gdb.exe"
```

## 8. 推荐的最终配置

### 8.1 推荐 tasks.json

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "type": "shell",
      "label": "task g++",
      "command": "D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin/g++.exe",
      "args": [
        "-g",
        "-I",
        "${workspaceFolder}/include",
        "${workspaceFolder}/src/*.cpp",
        "-o",
        "${workspaceFolder}/src/main.exe"
      ],
      "options": {
        "cwd": "${workspaceFolder}"
      },
      "problemMatcher": ["$gcc"],
      "group": "build"
    }
  ]
}
```

### 8.2 推荐 launch.json

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "g++.exe build and debug project",
      "type": "cppdbg",
      "request": "launch",
      "program": "${workspaceFolder}/src/main.exe",
      "args": [],
      "stopAtEntry": false,
      "cwd": "${workspaceFolder}",
      "environment": [],
      "externalConsole": true,
      "MIMode": "gdb",
      "miDebuggerPath": "D:/Work/Dev-Tools/Cpp/x86_64-8.1.0-release-posix-seh-rt_v6-rev0/mingw64/bin/gdb.exe",
      "setupCommands": [
        {
          "description": "Enable pretty-printing for gdb",
          "text": "-enable-pretty-printing",
          "ignoreFailures": true
        }
      ],
      "preLaunchTask": "task g++"
    }
  ]
}
```

## 9. 本次问题的核心经验

### 9.1 不要把编译器目录和项目目录混在一起

错误理解：

```txt
cwd = g++ 所在目录
```

更合理的理解：

```txt
command = g++ 所在位置
cwd = 当前项目根目录
args = 源码、头文件、输出文件的位置
```

也就是：

```txt
command 指向编译器
miDebuggerPath 指向调试器
cwd 指向项目根目录
program 指向生成的 exe
args 指向源码和编译参数
```

### 9.2 路径分隔符尽量统一用 `/`

在 VS Code 配置中，Windows 下也可以写：

```txt
D:/Work/xxx
```

这通常比：

```txt
D:\Work\xxx
```

更稳定。

原因是：

```txt
PowerShell 能识别 /
Git Bash 也更容易识别 /
JSON 中不需要重复转义
```

### 9.3 Git Bash 不是不能用于 C++，但不适合当前阶段

Git Bash 更适合：

```txt
Git 操作
前端项目命令
类 Unix 命令练习
```

当前 Windows + MinGW + VS Code C++ 调试，更适合：

```txt
PowerShell
cmd
```

尤其是在还没有系统学习 shell、路径规则、Makefile、CMake 之前，优先保证 C++ 编译调试链路稳定。

## 10. 最终结论

本次问题不是 C++ 代码问题，而是 VS Code C++ 调试链路配置问题。

完整链路可以理解为：

```txt
点击运行/调试
        ↓
launch.json 启动调试配置
        ↓
preLaunchTask 调用 tasks.json
        ↓
tasks.json 调用 g++.exe 编译源文件
        ↓
生成 main.exe
        ↓
launch.json 使用 gdb.exe 调试 main.exe
```

本次依次解决了：

```txt
1. g++.exe 路径被 Git Bash 错误解析
2. 源码路径在 Git Bash 下解析异常
3. PowerShell 下路径问题缓解
4. gdb.exe 路径配置错误
5. 最终成功编译并运行
```

最核心的复盘结论：

```txt
在 Windows 上使用 VS Code 学习 C++，优先使用 PowerShell。
g++.exe 和 gdb.exe 要来自同一套 MinGW。
command 管编译器路径，miDebuggerPath 管调试器路径。
cwd 最好指向项目根目录。
源码路径和输出路径建议基于 ${workspaceFolder}。
```
