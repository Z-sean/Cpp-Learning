# 头文件&源文件

- 头文件和源文件是Cpp项目的重要组成部分
- 继承于C，这种组织方式便于**代码重用&模块化**

---

## 头文件

- `.h`文件的作用是声明，包括

  - 类（class）的声明

  - 函数（functions）的原型（prototypes）

  - 模板（templates）的声明

  - 宏定义（#define）

  - 外部变量（extern variables）的声明

  - 内联函数（inline functions）

- 为了防止多个头文件重复声明，头文件通常包含以下预指令：

  - `#ifndef`-`#define`-`endif`

- ```cpp
  #ifndef EXAMPLE_H
  #define EXAMPLE_H
  
  class MyClass {
  public:
      MyClass(); // 构造函数声明
      void myFunction(); // 成员函数声明
  };
  
  #endif
  ```

## 源文件

- `.cpp`文件的作用是**实际的代码实现，即函数体、类的成员函数的实现等**

- 通常包括**必要的头文件**，以便编译器知道它们正在使用的函数、类等是如何声明的。

- ```cpp
  #include "example.h"
  #include <iostream>
  
  MyClass::MyClass() {
      // 构造函数实现
  }
  
  void MyClass::myFunction() {
      std::cout << "Hello from MyClass::myFunction!" << std::endl;
  }
  ```

  - 若是引入了官方文件，使用`<>`包裹
  - 若是引入了用户文件,使用`""`包裹

## 编译过程

- 编译器通常会首先处理源文件，查看`#include`指令，查找并**包含**所有需要的头文件，最后，编译器处理所有的源文件的实现代码，与**头文件进行匹配**

## 编译工具

- 头文件应该只包含声明，源文件应该包含声明
- 要使用头文件保护来避免头文件被重复声明
- 合理组织头文件和源文件可以提高项目的可维护性和可扩展性
- 编译时，确保所有的源文件都被编译，并且所有的头文件都被正确包含。
- `#pragma once` 和 宏定义（如 `#ifndef, #define, #endif`）都是用来防止头文件被重复包含的机制

## 宏定义与`#pragma once`

- Clion中自定义了宏定义模板，同时通过CMake对项目进行编译
- Visual Studio中使用`#pragma once`作为预定义模板，其底层工具是"MSVC"

---

### `#pragma once`

- `#pragma once` 是一个**非标准**的但广泛支持的预处理指令，它告诉编译器该头文件在单个编译过程中只应被包含一次。编译器在第一次遇到 `#pragma once` 时会记住该文件名，并在后续的包含操作中忽略它。

- 缺点是因为不是标准的一部分，在一部分编译器中不被支持

### 宏定义

- 首先检查一个特定的宏是否已定义，如果没有定义，则定义它并包含头文件的其余部分。如果宏已经定义，则跳过头文件的其余部分。
- 需要**为每个头文件生成一个唯一的宏名**，这可能会增加出错的机会（例如，如果两个头文件不小心使用了相同的宏名）。

## 具体编译过程

![](D:\Work\Computer-Learning\Cpp-Learning\Screenshots\GNU项目.png)

- 在大多数Linux发行版和Unix系统中，GCC和g++通常作为标准软件包的一部分进行安装。在Windows系统中，则可能需要下载并安装MinGW或Cygwin等工具来提供GCC和g++的支持。

- 使用 `g++` 编译 `main.cpp` 时，不需要把头文件写进编译命令；只要在源码中用 `#include` 引入，编译器会自动查找并包含它们

> 所有的源文件都需要编译，头文件会被自动查找并包含

- 如果你的头文件**位于非标准路径（即不在编译器的默认搜索路径中）**，你需要使用 `-I` 选项来指定额外的头文件搜索路径。
- 假设头文件 `example.h` 位于与 `main.cpp` 相同的目录下，或者位于编译器默认搜索的头文件路径中，可以简单地使用以下命令来编译 `main.cpp`

```bash
g++ main.cpp -o myprogram
```

- `-o myprogram` 指定了输出文件的名称,如果你没有指定 `-o` 选项，编译器通常会生成一个名为 `a.out` 的可执行文件（在 Unix-like 系统中）

---

- 如果你的头文件位于不同的目录，比如 `include` 目录，并且 `main.cpp` 中包含了 `#include "example.h"`，你需要使用 `-I` 选项来告诉编译器在哪里查找这个头文件

```bash
g++ -Iinclude main.cpp -o myprogram
```

- `-Iinclude` 告诉编译器在 `include` 目录下查找头文件。注意，**`-I` 选项后面紧跟的是目录名，而不是文件名**

- 若项目包含多个cpp文件和多个头文件，同时文件位于不同目录下，并且链接了外部库，那么需要这么做:
  - 头文件目录用 `-I`，库文件目录用 `-L`，库名用 `-l`。普通多文件项目通常只需要写上所有 `.cpp`，再用 `-I` 指定头文件目录即可。

- ```cpp
  g++ main.cpp -I include -L lib -lmylib -o main
  
  g++ main.cpp src/add.cpp src/user.cpp -I include -o main
  ```

## CMake

- `CMake`是一个跨平台的自动化构建系统，它使用`CMakeLists.txt`文件来描述构建过程。
- ![](D:\Work\Computer-Learning\Cpp-Learning\Screenshots\CMake可执行文件.png)

```bash
mkdir build  # 创建一个名为build的目录（推荐）
cd build
cmake ..     # 使用上级目录中的CMakeLists.txt配置项目
```

- 以上指令完成后，CMake后构建一个系统，该系统用于构建项目

> CMake 读取 `CMakeLists.txt` 中声明的源文件、头文件路径、编译选项和链接信息，生成一套项目构建规则；构建工具读取这些规则后，按照规则调用编译器和链接器完成项目构建
