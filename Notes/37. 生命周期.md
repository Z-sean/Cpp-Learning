# C++ 笔记：对象生命周期与作用域 (Object Lifetime / Scope)

## 1. 栈分配与生命周期管理

在 C++ 中，基于栈（Stack）分配的对象，其生命周期完全由它的**作用域 (Scope)** 决定。

- **作用域的定义**：作用域可以是一个函数、一个 `if` 语句块、一个 `for` 循环，甚至仅仅是一对空的大括号 `{ }`。
- **自动销毁机制**：当程序执行流程离开该作用域时，在这个作用域内声明的所有栈变量都会被自动弹出销毁，并调用其析构函数。

## 2. 堆分配的对比

与栈分配不同，使用 `new` 关键字在堆（Heap）上分配的对象不受作用域限制。它们会一直存在，直到你显式地调用 `delete` 去释放它们。

## 3. 常见陷阱：返回局部变量的指针

**绝对不要在函数中创建一个基于栈的数组或变量，然后将它的指针返回**。一旦函数执行结束，作用域内的栈内存就会被回收，导致返回的指针变成一块无效的悬空内存。如果一定要返回指针，必须将该数据分配在堆上，或者将数据传到上层作用域中。

## 4. 利用栈生命周期 (RAII 机制)

我们可以利用“栈对象离开作用域一定会调用析构函数”这一特性，来自动完成许多清理工作。这在 C++ 中是一种极其强大的模式：

- **作用域指针 (Scoped Pointer) / 智能指针**：用一个栈对象去包装一个堆指针，在栈对象的析构函数中自动 `delete` 堆内存，从而防止内存泄漏（例如 `std::unique_ptr`）。
- **作用域计时器 (Scoped Timer)**：在构造函数中开始计时，在析构函数中停止计时并输出结果。只需在函数开头声明一个对象，就能自动计算整个作用域的执行时间。
- **作用域锁 (Scoped Lock)**：在进入作用域时自动加锁 Mutex，离开作用域时自动解锁，防止多线程死锁。

## 5. 示例代码

### 栈与堆的对象生命周期

```cpp
#include <iostream>

class Entity {
public:
    Entity() { std::cout << "Created Entity!" << std::endl; }
    ~Entity() { std::cout << "Destroyed Entity!" << std::endl; }
};

int main() {
    {
        // 1. 在栈上分配，生命周期受作用域控制
        Entity e;
    } // 作用域结束，自动调用析构函数，打印 "Destroyed Entity!"

    // 2. 在堆上分配，生命周期不受作用域控制
    Entity* e2 = new Entity();

    // 必须手动释放，否则会发生内存泄漏
    delete e2;

    return 0;
}
```

### 自定义作用域指针 (Scoped Pointer) 示例

```cpp
// 编写一个简单的包装类，利用栈生命周期自动释放堆内存
class ScopedPointer {
private:
    Entity* m_Ptr;
public:
    ScopedPointer(Entity* ptr) : m_Ptr(ptr) {}
    ~ScopedPointer() {
        delete m_Ptr; // 当 ScopedPointer 被销毁时，自动清理内部包装的堆内存
    }
};

int main() {
    {
        // 在堆上创建了 Entity，但由栈上的 ScopedPointer 管理
        ScopedPointer e = new Entity();
    } // 作用域结束，ScopedPointer 触发析构，底层的 Entity 被自动 delete，完美避免内存泄漏

    return 0;
}
```
